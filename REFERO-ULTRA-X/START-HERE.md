
# REFERO ULTRA X 2.3 — START HERE

This is the mandatory entry point when a user says “start REFERO”, “run the skill”, “use REFERO ULTRA X”, or asks for a design/UI implementation using this system.

## Mandatory bootstrap protocol

1. Read `AGENTS.md`, `CORE.md`, `PROJECT.md`, `MODES.md`, `WORKFLOW.md`, and `REFERO-RESEARCH.md`.
2. Read the complete `REFERO-RESEARCH.md` MCP protocol and execute it against the **currently available Refero MCP tools**. Do not merely mention Refero MCP in the plan. Inspect available tool descriptions/schemas first, then invoke appropriate tools for the task.
3. Read relevant specialist modules before acting. For ambitious UI work this includes at minimum:
   - `CREATIVE-EXCELLENCE.md`
   - `CREATIVE-WEB.md`
   - `REFERENCE-INTELLIGENCE.md`
   - `DESIGN-SYSTEM.md`
   - `MOTION-RECONSTRUCTION.md` and `MOTION-SYSTEM.md` when motion is relevant
   - `IMAGE-TO-CODE.md` when reconstructing or adapting visual references
   - `VISUAL-QA.md` and `BENCHMARK-SUITE.md` for validation
4. Inspect the actual project and classify the task before choosing references.
5. Research **fresh, task-relevant references**. The example references in `BENCHMARK-SUITE.md` are evaluation fixtures, not default design templates.
6. Present a compact evidence-based research summary and two materially different creative directions for high-impact work. Select a direction based on the product, not habit.
7. Implement, run the application when possible, inspect rendered output, fix the highest-impact discrepancies, and report what was actually verified.

## Non-negotiable rules

- **Do not default to Exat, Lando Norris, or Messenger.** They are benchmark examples only. Use them only when the task specifically benefits from their demonstrated traits or the user asks for them.
- **Do not use Refero MCP as a decorative mention.** Search it and inspect returned records when the configured tools are available. If the MCP is unavailable or fails, state that explicitly, then use available alternatives; never claim MCP research was completed.
- **Do not select the first result automatically.** Generate multiple queries, collect candidates, compare their relevance, and inspect details/screens/flows where tools support it.
- **Do not assume MCP tool names.** Discover the current exposed tools and their schemas at runtime; names can change.
- **Do not stop after inspiration research.** Convert findings into a project-specific reference map, creative thesis, implementation plan, and verifiable acceptance criteria.
- **Do not force a cinematic/3D aesthetic onto every product.** Select from a wide design space, including editorial, typographic, minimal, data-dense, tactile, playful, brutalist, cinematic, spatial, and hybrid directions.
- **Do not claim a tool call, screenshot, test, or visual inspection happened unless it actually happened.**

## Required task output

Before significant implementation, maintain a short `REFERENCE-RESEARCH.md` (or project-appropriate equivalent) containing:
- task intent and research questions;
- MCP availability and tools actually used;
- queries and source identifiers/URLs;
- at least 5 candidates when the MCP can return sufficient results, or a transparent reason for fewer;
- candidate scores and selection rationale;
- reference roles and what is explicitly rejected;
- creative thesis and two alternative directions;
- unknowns and confidence levels.

Do not create this file in the skill root for unrelated projects; keep project-specific artifacts in the target project.
